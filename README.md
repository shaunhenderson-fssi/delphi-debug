# Delphi Debug for VS Code

`delphi-debug` is an early-stage VS Code extension for navigating Delphi
applications using the debug information from a compiled executable's MAP file.
Its eventual goal is to provide a Delphi debugging experience in VS Code,
including source navigation, executable address translation, symbol resolution,
breakpoints, and call-stack display.

The extension currently supports MAP-file analysis and address/source
navigation. It does not yet launch or debug an executable.

## Using Delphi Debug with RAD Studio

RAD Studio does not have to compile or run the application. If the project has
a build script, that script can build the Delphi executable while VS Code is
used for source navigation and address analysis.

RAD Studio may still be needed to review or maintain the project options that
control detailed MAP generation and debug symbols. The generated project
settings must be used by the build script; the extension cannot enable those
RAD Studio compiler options by itself.

The example workspace layout used here is:

```text
C:\develop\inca\             Delphi .pas source files
C:\apps\inca\bin\            Compiled .exe and generated .map files
```

### 1. Produce matching debug information

Use RAD Studio to configure the project:

1. Open the Delphi project.
2. Open **Project > Options > Building > Delphi Compiler > Linking**.
3. Enable a detailed MAP file.
4. Enable any required debug-symbol or debugging options for the build script.
5. Save the project options and confirm how the build script invokes the Delphi
   compiler with those settings.

Then build the executable using the VS Code build script (.vscode\build.ps1):

```text
build-script source: C:\Develop\INCA\
build output:        C:\Apps\INCA\Bin\
```

After the build, keep the following outputs associated with the same build:

- the Windows `p1.exe`;
- the generated `p1.map`;
- the Delphi `*.pas` source files;
- generated or included units referenced by the project.

Use one build consistently. If the executable, MAP file, or source changes, or
if the project is rebuilt, regenerate and select the corresponding new MAP file.
Address and line information is not reliable across builds.

RAD Studio option names vary by version. Look in **Project Options** for linking
settings such as **Map file**, **Detailed**, or **Debug information**. If
**Detailed** is not available under the Delphi compiler options, use the MAP
file setting provided by the installed RAD Studio version.

### 2. Open the project in VS Code

1. Add both default locations to the VS Code workspace:
   - `C:\develop\inca\` for the Delphi `.pas` files;
   - `C:\apps\inca\bin\` for the compiled `p1.exe` and `p1.map` file.
2. In VS Code, choose **File > Add Folder to Workspace...** and add both folders.
3. Save the multi-root workspace if you plan to use this layout regularly.
4. Open a `.pas` source file from `C:\Develop\INCA\`.

VS Code searches the workspace for `.map` and `.pas` files automatically.
Nested folders are supported. If the source and build-output folders cannot be
opened together because they are outside the repository, use VS Code's
multi-root workspace support.

### 3. Install and enable the extension

During development, enable the extension from the repository:

1. Run `npm install`.
2. Run `npm run compile`.
3. Press `F5` in VS Code.
4. In the **Extension Development Host** window that opens, open the Delphi
   workspace folder again.
5. Confirm that the extension is active under **Extensions** by locating
   **delphi-debug**.

Until this extension is published in the VS Code Marketplace, it will not
appear from a normal Marketplace search. The development-host method above is
the current installation method for this repository.

### 4. Select the MAP file

1. Open the Command Palette with `Ctrl+Shift+P` or `Ctrl+.`.
2. Run **Delphi Debug: Select MAP file**.
3. Choose the MAP generated by the same build as the executable.
4. Alternatively, choose **Browse for a .map file...** and select the file.

The selected path is remembered for the workspace. Select it again whenever you
switch to another build.

### 5. Navigate from Pascal source

1. Open a `.pas` file in the workspace.
2. Place the cursor on a source line that RAD Studio compiled with line
   information.
3. Run **Delphi Debug: Current line info** to show:
   - source text;
   - resolved executable address;
   - containing symbol.

Run **Delphi Debug** for the same source-to-address lookup with the general
lookup notification.

### 6. Navigate from a runtime address

1. Copy an executable or runtime address reported by Windows, a crash dump, a
   disassembler, or another debugging tool.
2. Run **Delphi Debug: Go To Runtime Address**.
3. Enter the address, for example `00FD72AC`, `0001:00FD72AC`, or
   `0x00FD72AC`.
4. The extension finds the nearest mapped source location and opens the matching
   `.pas` file, if that file exists in the workspace.

If Windows addresses are provided in another form, use the hexadecimal offset
portion that matches the MAP file. The address input validator accepts one
optional segment and one optional `0x` prefix.

### 7. Troubleshooting the migration workflow

| Problem | Check |
| --- | --- |
| No MAP files appear | Build the Delphi executable again and verify that the `.map` file is in the workspace or under a nested folder. |
| No source mapping is found | Confirm that source, executable, and MAP file are from the same build. Try another compiled line. |
| Source file is not found in the workspace | Add the Delphi source folder to the workspace; navigation matches `.pas` files by base file name. |
| Symbol is `<unknown symbol>` | The address may be outside a symbol range or absent from the MAP file's symbol entries. |
| Address resolves to the wrong line | Select the correct MAP file. MAP files can only map code locations included in line-number information. |

## Current functionality

- Select a Delphi `.map` file discovered in the workspace, or browse for one.
  The selected file is saved for the current workspace.
- Load and parse line-number and public symbol entries from Delphi MAP files.
- Convert a current `.pas` source line to its nearest mapped address.
- Convert a runtime address to its nearest mapped source line and containing
  symbol.
- Open the matching `.pas` file in the workspace and position the cursor on the
  mapped source line.
- Display source text, the resolved address, and the resolved symbol in VS Code.
- Log navigation activity to the **Delphi Debug** output channel.

## Commands

Run these commands from the VS Code Command Palette (`Ctrl+Shift+P`):

| Command | Purpose |
| --- | --- |
| **Delphi Debug: Select MAP file** | Choose a MAP file from the workspace or browse for one. |
| **Delphi Debug** | Resolve the active `.pas` file and line to a MAP-file address and symbol. |
| **Delphi Debug: Current line info** | Show the active source line, resolved address, and symbol. |
| **Delphi Debug: Go To Runtime Address** | Enter an address and navigate to the nearest mapped `.pas` source line. |

Runtime addresses can be entered with or without a segment prefix or `0x`
prefix, for example:

- `00FD72AC`
- `0001:00FD72AC`
- `0x00FD72AC`

## Intended debugging workflow

The long-term aim is for the extension to inspect a compiled Windows Delphi
executable and provide a VS Code debugging session that can:

- resolve addresses and source locations in both directions;
- locate symbols and containing procedures;
- navigate source by executable address;
- map breakpoint locations into executable addresses;
- launch or attach to the Windows application;
- display source breakpoints and active execution locations;
- show a call stack and variable or register information;
- use Delphi symbols and source paths in MAP files to correlate runtime state
  with `.pas` source.

## Requirements and limitations

- The Delphi project source and matching `.pas` files should be available in the
  VS Code workspace.
- A corresponding Delphi-generated `.map` file is required for the current
  navigation features.
- Source navigation currently matches `.pas` files by base file name.
- Address and line mappings may be approximate: MAP files contain mappings for
  compilable locations, so an unmapped requested line uses the nearest mapped
  location.
- Symbol resolution uses the last symbol whose start address does not exceed the
  requested address.
- Executable launch, attachment, actual breakpoint management, stepping,
  evaluating expressions, variables, and call stacks are not implemented yet.
- Windows `.exe`, source, and MAP file paths must come from the same build so
  that addresses are consistent.

## Running from source

From the repository root:

```powershell
npm install
npm run compile
npm test
```

Press `F5` in VS Code to run the extension in an Extension Development Host.
